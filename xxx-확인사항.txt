#################################
복잡한 도메인 기능 추가시
#################################
쿠폰 관리와 같은 복잡한 도메인 기능을 추가할 때, Agentic Mode는 단순히 코드를 짜는 것을 넘어 기획(설계)부터 구현, 검증까지 체계적으로 진행합니다.

사용자님은 **"비즈니스 요구사항(규칙)"**만 준비해주시면 됩니다. 나머지는 제가 주도적으로 문서화하고 구현하며 사용자님께 컨펌받는 식으로 진행됩니다.

1. 준비하실 것 (Requirements)
복잡한 구현일수록 첫 단추가 중요합니다. 다음과 같은 핵심 비즈니스 규칙을 알려주시면 됩니다. (지금 당장 완벽하지 않아도 됩니다.)

발행(Issuance): 관리자가 수동 발행? 회원가입 시 자동 발행? 특정 이벤트 당첨?
유형(Type): 정액 할인가(1000원) vs 정률 할인가(10%)
만료(Expiration): 발급 후 N일? 특정 날짜까지? 만료 처리는 배치(Batch)로 자동화?
연동(Integration): 주문서(Order)에서 적용? 특정 상품(Product)에만 적용 가능?
2. 진행 방식 (How to do it in Agentic Mode)
제가 Agentic Mode로 전환하여 다음과 같은 3단계로 작업을 수행합니다.

Phase 1: Planning (설계 및 합의)
가장 중요한 단계입니다. 코드를 치기 전에 제가 먼저 설계를 제안합니다.

task.md
 생성: 쿠폰 기능을 Backend(DB, API), Frontend(Admin, User), Batch 등으로 세분화하여 할 일 목록을 만듭니다.
implementation_plan.md 작성:
DB Schema: Coupon, MemberCoupon, CouponHistory 등 테이블 구조 제안.
API Spec: 발행, 조회, 사용, 취소 API 정의.
UI/UX: 관리자 페이지의 쿠폰 등록 폼, 사용자 쪽의 쿠폰 선택 UI 설계.
사용자 리뷰 (Review): 제안된 설계가 맞는지 사용자님께 확인을 요청합니다. (이때 요구사항을 수정하실 수 있습니다.)

Phase 2: Execution (구현)
설계가 승인되면 제가 순차적으로 개발을 진행합니다.

Step 1: DB 마이그레이션 (.sql) 파일 생성 및 Entity/Repository 구현
Step 2: 핵심 비즈니스 로직 (발행, 사용, 유효성 검증) Service 구현
Step 3: Admin Frontend (쿠폰 정책 관리, 발행 내역 조회) 구현
Step 4: User Frontend (주문 시 쿠폰 적용) 구현

Phase 3: Verification (검증)
테스트 코드를 작성하거나, 실제 시나리오대로 동작하는지 확인 후 walkthrough.md에 결과를 정리하여 보고합니다.
바로 시작해볼까요? 지금 바로 **"쿠폰 관리 시스템 기획해줘"**라고 말씀하시고, 생각하고 계신 **간략한 요구사항(예: 정률/정액 할인 필요, 상품별 쿠폰 등)**을 덧붙여 주시면 제가 Planning 단계부터 시작하겠습니다.
